# 实验方法与运行方式汇总

## 1. 实验目标

当前实验目标是在合法设备可靠通信的前提下，提高非法设备窃听时的安全误码率。

核心安全指标为：

```text
secure_BER = min(BER, 1 - BER)
```

其中：

- `BER = 0` 表示非法设备完全解对。
- `BER = 1` 表示非法设备完全解反，取反后仍可恢复。
- `secure_BER = 0` 表示完全泄露。
- `secure_BER = 0.5` 表示接近随机猜测，安全性最好。

因此实验优化目标是让所有非法设备到所有合法设备链路中的最小 `secure_BER` 尽量接近 `0.5`。

## 3. 随机 Probe Hopping 实验

### 3.1 实验思想

随机 probe hopping 的思想是：

1. 对每个合法位置组合搜索多个合法可靠 probe set。
2. 每个 probe set 都要求合法设备 BER 为 0。
3. 发送每个 bit block 时，随机从 probe pool 中选择一个 probe set。
4. 评估非法设备解码每个合法设备信息时的 BER 和 secure BER。

当前随机选择逻辑为有放回均匀随机抽样：

```python
selected_entries = [rng.choice(list(probe_pool)) for _ in bit_blocks_pm]
```

含义：

- 每个 bit block 独立随机选择一个 probe set。
- 同一个 probe set 可以连续多次被选中。
- 不保证每个 probe set 使用次数相同。
- 不根据非法设备风险做优化。

## 4. test-4 三 Worker 并行运行

### 4.1 并行目的

四位置组合实验较慢，因此 `test-4` 的随机 hopping 脚本支持 worker 拆分。

核心逻辑：

```python
combination_idx % worker_count == worker_index
```

因此只要三个进程使用相同的 `--combination-count` 和 `--worker-count 3`，并分别设置 `--worker-index 0/1/2`，它们处理的位置组合不会重叠。

### 4.2 运行方式

打开三个 PowerShell 窗口，分别运行：

```powershell
python "E:\LuminaLink\Position_fingerprint_experiment\test-4\random_probe_hopping_yellow_4pos.py" --combination-count 60 --worker-count 3 --worker-index 0
```

```powershell
python "E:\LuminaLink\Position_fingerprint_experiment\test-4\random_probe_hopping_yellow_4pos.py" --combination-count 60 --worker-count 3 --worker-index 1
```

```powershell
python "E:\LuminaLink\Position_fingerprint_experiment\test-4\random_probe_hopping_yellow_4pos.py" --combination-count 60 --worker-count 3 --worker-index 2
```

## 5. test-3 离线 Probe 调度实验

### 5.1 实验思想

随机 hopping 不考虑不同 probe set 对非法链路的安全互补性，因此新增离线 probe 调度策略。

流程：

1. 使用已有 probe pool。
2. 统计每个 probe set 对每条非法链路的 BER。
3. 求使用比例 `p_k`，最大化所有非法链路中的最小 secure BER。
4. 根据比例生成固定长度调度序列。
5. 在线阶段只按序列循环查表。

目标函数：

```text
maximize_p min_{e,l} min(
    sum_k p_k BER_{e,l}(S_k),
    1 - sum_k p_k BER_{e,l}(S_k)
)
```

在线使用方式：

```python
probe_set_id = schedule_sequence[t % schedule_length]
```

## 6. test-4 安全感知候选库 + 离线调度实验

### 6.1 实验动机

仅在已有小 probe pool 上做调度，提升有限。原因是调度算法无法突破 probe pool 本身的安全上限。

因此新增 test-4 实验：

```text
先生成合法可靠候选库
再从候选库中筛选安全互补 probe set
最后生成离线调度序列
```

### 6.2 脚本

```text
E:\LuminaLink\Position_fingerprint_experiment\test-4\security_aware_candidate_pool_schedule_4pos.py
```

该脚本不修改原 test-4 实验代码。

### 6.3 候选库边界

候选库阶段采用宽松策略：

硬要求：

```text
合法位置 BER = 0
probe set 不重复
probe 数量固定
probe 间隔满足 min_probe_interval
```

不再把 zero leak 数量作为硬拒绝条件。

记录但不拒绝的指标：

```text
min_secure_ber
average_secure_ber
zero_leak_route_count
worst_route
每条非法链路 route_min_ber
```
